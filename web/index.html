Linux: one-time setup needed. Chrome can't open the keyboard until you allow it

Linux only lets root open USB HID devices by default. Run this once in a terminal, then unplug and replug the keyboard:

sudo tee /etc/udev/rules.d/70-w909.rules <<'EOF'
SUBSYSTEM=="hidraw", ATTRS{idVendor}=="b6a4", ATTRS{idProduct}=="4100", MODE="0660", TAG+="uaccess"
SUBSYSTEM=="hidraw", ATTRS{idVendor}=="b6a4", ATTRS{idProduct}=="4101", MODE="0660", TAG+="uaccess"
EOF
sudo udevadm control --reload-rules && sudo udevadm trigger
  • This lets the logged-in desktop user open the W909; it doesn't affect other devices.
  • Chrome or Chromium installed as a Snap or Flatpak may still be blocked by its sandbox. If connecting fails, use the .deb/.rpm build of Chrome, Edge or Brave.
  • If the keyboard doesn't appear in the list at all, check lsusb | grep -i b6a4 shows it.
Windows: if the keyboard won't connect
  • No driver is needed. Windows' built-in keyboard driver is enough.
  • Quit the vendor app (SXS-W909) if it's running, including from the system tray. It can hold the keyboard open.
  • Use the USB cable, plugged directly into the computer rather than through a hub or monitor.
  • In the browser's device list, pick “W909 Pro USB”. If it's listed more than once, pick each in turn.
  • Still stuck? Restart the browser after plugging the keyboard in, and make sure you're using Chrome, Edge, Brave or Opera.
Read-only: connected through the 2.4G receiver. The keyboard shows its settings over the receiver but ignores changes, so editing is turned off. To make changes, plug in the USB cable, then and choose “W909 Pro USB”.
